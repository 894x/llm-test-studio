# 多类别计划项与启动进度

## 本次变更

测试计划支持编辑，并按顺序配置多个计划项。每项独立命名，选择功能测试（用例或套件）或性能测试，配置各自参数，并选择失败后继续或停止后续项。可复制、排序、删除计划项；复制产生新身份，编辑和排序保留原身份。内置计划以另存为方式生成用户计划。

例如 K3 准入计划可以包含“基本测试（失败停止）”“并发 4 压测”“并发 8 压测”。整份计划共用协议、运行目标与随机种子；渠道、凭据和模型仍在启动运行时选择。性能项复用现有性能参数表单与执行器，包括负载、预热和 SLO 配置。

执行按项串行，同一项内按其负载策略并发。功能项以测量阶段断言和 SLA 判定失败，性能项以执行结果和 SLO 判定失败；预热记录不直接决定后续项是否停止。取消终止整个运行。停止后未执行的项目保留“未开始”，不会伪装成失败或成功。

一份计划产生一个 Run 和一份组合报告。报告保留每项的配置、结论和执行状态；性能项包含完整性能报告，HTML 导出包含性能指标及样本。性能检查点单独保存，运行列表的请求数使用实际性能测量进度，避免把检查点当成请求。历史报告不会用本次规则重新生成。

## 文件、存储与协议兼容

| 边界 | 支持路径与限制 |
| --- | --- |
| Plan 文件 | 读取已发布 `file_schema_version: 1` 和当前版本 2。版本 1 的整计划性能配置在内存中转换为一个性能项，稳定地复用计划 ID；原用例和套件项保持身份、内容和顺序。缺失、未知、较新版本或版本 1 携带版本 2 专属字段明确拒绝。 |
| 保存计划 | 新文件写版本 2。读取旧文件不会写回；第一次明确编辑版本 1 文件时，先在相邻 `<plans目录>.v1-backups/` 写入并核对原始字节，再原子替换目标文件。备份名含计划 ID 和原文 SHA-256；失败保留原文件。文件锁和修订号检查覆盖该过程。 |
| SQLite | 此功能没有新增或重写数据库 schema。当前仍为既有 `user_version=2`；新增内容位于既有 JSON 文档中。既有迁移链与冻结基线不变。 |
| 快照与报告 | 为计划项增加可选名称、失败策略、性能配置和性能结果。旧功能测试快照/报告保持读取；现存历史 fixture 保留。旧程序不能保证读取新混合运行和报告。 |
| 远程 runner | 新计划项字段要求 `mixed_plan_items` 能力；每项还检查对应负载、预热等能力。未升级 runner 在提交前拒绝，不能忽略失败停止策略。先升级 runner，再使用新计划项功能。 |
| 桌面 binding | 新增独立的 `GetStartupProgress` 查询，与前端同包发布。查询不等待业务 repository 初始化完成。旧的整计划性能命令在入口转换为单项配置；更新只适用于原单性能项，保留项目身份，不能覆盖混合计划。 |

版本 1 文件适配暂不设移除日期。后续移除须遵守项目兼容政策的公告和过渡要求。此变更作为新增功能发布，不应作为旧程序支持混合文件/报告的承诺。

恢复单个旧计划时，先退出应用和其他写入者，保留当前文件，再用对应计划的已核验备份替换；恢复会失去该计划升级后的编辑。整工作区降级需要匹配旧二进制及升级前完整备份，不能只恢复计划文件后让旧程序读取新运行。数据库备份与历史升级范围见 [兼容政策](../compatibility-policy.md)。

## 打开时的进度

启动页面显示真实阶段：检查版本和完整性、初始化、创建并校验备份、迁移、校验、读取目录、打开历史记录、恢复任务。每 400ms 查询一次，同时显示已用时间和适用的数据版本变化；完成后进入工作区。

这些阶段来自实际迁移与初始化调用，不显示无依据的百分比。失败保留最后阶段，统一展示错误、重试和日志入口；不重复显示运行列表空态和多份同一错误。回调只包含阶段、版本和时间，不包含数据库路径、内容或凭据。此功能不会放宽未知数据库的拒绝规则，也不自动重置或修复用户数据库。

## 验证范围

- 真实 SQLite 与本地 HTTP 模型替身：混合成功、基本项失败继续/停止、性能项失败继续/停止、SLA 停止、压测中取消后保留检查点、组合报告及实际进度。
- 真实 runner HTTP 提交、能力检查、任务结算、组合报告下载与 HTML 导出。
- 版本 1 重复只读打开、首次编辑备份、备份失败保持原文、恢复原文，以及未知/不合法版本拒绝。
- 真实历史数据库 fixture 的迁移阶段与重复打开；启动初始化阻塞时仍可查询进度，失败保留阶段。
- 浏览器编辑器创建、复制、保存和重新打开；1440、1024、960 宽度及深色外观。启动中与失败界面通过 binding 替身验证。

上述测试使用临时数据库和本地 HTTP 服务，没有调用付费模型，也没有迁移实际用户数据库。浏览器验证不代表原生 Wails/WebView 安装升级验收。

### 原生桌面补充验证（2026-10-18）

使用 Wails v2.15.0 新构建打开已有用户工作区，先完成 SQLite online backup、完整性和逐表内容校验，并备份 authored 文件及配置。现有库已为 schema 2，本次打开没有执行数据升级。

真实 WebView2 验证发现：内置及旧版性能计划的空参数在目录 DTO 中序列化成 `null`，导致前端拒绝整份目录并显示工作台打开失败。修复限于目录输出边界，将空参数规范为 `{}`，不修改原计划或数据库；补充实际 JSON 序列化回归测试，并用原生返回的目录验证前端解析。

使用实际 Go binding 的原生窗口验证了运行列表、22 个计划、旧 K3 计划编辑、添加性能项与失败策略选择、总览、模型与渠道、用例、历史报告列表及详情。编辑草稿关闭而未保存，也未发起模型调用。UI 检查通过仅启用本机 CDP 的诊断构建完成，随后关闭诊断窗口并启动无调试端口的生产构建。

验证后，51 张数据库表的全部行值与备份一致，12 个 authored 文件逐字节一致；包括 73 次运行、71 份计划报告、54 份性能报告和 6480 条用例结果。迁移记录保持原样。此次证据覆盖已有工作区原生读取及编辑交互；实际安装包升级、旧库原生迁移进度和断电恢复仍不能由此次打开代替验收。
