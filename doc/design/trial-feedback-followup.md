# 试用反馈后续实现

## 当前行为

- 总览的模型、渠道、用例、套件、计划、运行和报告可点击进入对应列表；就绪度链接打开对应目录页签，活动运行定位具体记录。目标页可返回总览，已访问页面保留搜索、选择和滚动位置。
- 用例支持多行说明，建议写清目的、前置条件、通过标准和适用限制；常用内置用例补充说明。说明和实际测试定义分开展示，执行断言没有随文案改变。
- 运行、报告、快速测试提供“移入回收站”。确认框展示所属整次测试及关联报告数量，后端重新检查终态后写入。测试仍在执行或状态未确认时拒绝移除。
- 回收站可以恢复整次测试。移除和恢复影响当前工作区的桌面历史可见性，包括总览、运行、报告、快速测试和渠道对比；原始执行事实、附件、CLI/runner 读取及远程节点数据保留。没有彻底删除和释放磁盘空间功能。

## 格式和升级

这些变更随下一次次版本发布，遵循 [兼容政策](../compatibility-policy.md)。

Case 文件支持原有 schema 2，新增说明使用 schema 3。无说明用例继续写 schema 2，原有语义摘要和派生修订不变；清空说明后重新保存为 schema 2。schema 2 中出现说明字段、schema 3 缺少有效说明、未知版本或未知字段会明确拒绝，不修改原文件。旧 schema 2 的读取路径继续保留，暂无移除计划。

新执行把说明与 Case 定义一起冻结到运行快照，目录后续修改不会改写旧运行和旧报告。现有 Case/Suite/Plan 身份和引用保留。带说明的远程任务要求 runner 声明 `case_descriptions` 能力，缺少能力在提交前拒绝；无说明的任务不增加该能力要求。共享 runner 上需要查看这些新任务的桌面端也应先更新，旧严格解码器不能识别新增说明字段。旧文件、旧快照和旧报告继续可读。

SQLite 追加不可变迁移 `0004_history_recycle`，版本 1、2、3 的来源和校验和保持冻结，升级入口共用现有预检、排他控制、一致备份和事务流程。版本 4 只新增回收站归属及成员索引，原始业务行和历史结论保留。v3 回归来源为 `82e10184` 的真实结构 fixture；已有 v1/v2 回归来源继续保留。

降级需退出所有写入进程，恢复升级前验证通过的数据库备份以及对应的 Case 文件备份，再使用匹配的旧二进制。旧程序不能直接读取 schema 4 数据库或带说明的 schema 3 Case/新任务快照；恢复旧备份会丢失备份后的新增写入。没有新增 CLI 选项或改变退出码，也没有弃用原有字段。

## 验收边界

自动化验收使用临时数据库和本地模拟数据，覆盖格式兼容、说明冻结、runner 能力门禁、升级备份/回滚/恢复、终态限制、整组可见性、迟到同步及页面恢复。实际用户数据迁移、真实远程 runner 升级、原生安装包升级和断电/磁盘满不由这些测试替代；发布前分别执行。

### 2026-10-30 验证记录

- Go 的 `casecodec`、`jobcontract`、`casecatalog`、`catalog`、`workspace` 全包测试通过；桌面 `bridge`、`bootstrap` 全包通过。
- SQLite 的全部迁移、升级、Schema、查询索引测试，以及回收站和桌面可见性定向测试通过。全 SQLite 包曾因测试期间主机内存不足失败，未记为全包通过；按独立进程分范围复测的结果如上。
- 前端全量运行 69 文件、1028 项：1026 项通过，2 项读取到运行期间修改前的实现；源码稳定后复跑对应 5 文件、206 项全部通过。最新 App 下钻返回、旧总览请求隔离、移除后迟到报告事件及恢复链路的 3 项集成测试通过。
- TypeScript 和生产 Vite 构建通过，构建输出在临时目录，未替换正在运行的桌面应用资源。Lint 仅保留既有 `entry-case-table.tsx` 的状态同步警告，本批修改没有新增警告。

代码审查发现并修复了回收后迟到报告状态重新显示、总览旧轮询覆盖新计数，以及恢复任务复用旧分页请求三处竞态。另修正一个既有进度回滚测试的专用 fixture，使其符合当前快速任务契约，没有放宽生产校验或修改共享 fixture。
