# 桌面端界面系统

本文定义 LLM Test Studio 桌面端的可执行视觉与交互基线。界面风格遵循
`town-ui-design` 的产品工具语言；组件实现使用 React、Tailwind CSS 与
shadcn/ui，不引入 Naive UI 运行时，也不复制 Animetown 的组件代码。

## 产品界面方向

- 默认呈现为紧凑、克制的工具工作区，而不是运营数据大屏或卡片式 Dashboard。
- 主要任务是选择计划、启动运行、观察进度、检查结果与证据；当前任务始终占据最大空间。
- Model 与 Channel 是独立对象。任何页面都不得再把模型名称、渠道地址和凭据混成同一实体。
- 轻色与暗色主题具有同等地位。初始偏好为 `system`，解析结果只有 `light` 或 `dark`。
- React 只保存交互与展示状态；校验、运行状态机、持久化、凭据和报告逻辑均来自 Go Application Core。

## 单行窗口标题栏

- 桌面窗口使用 Wails v2.15.0 的无边框窗口；应用标识、主导航、应用操作及窗口操作共用一条 48px 标题栏。产品名称单行显示，不再重复展示系统标题和副标题；紧凑窗口保留产品图标。
- 应用操作与右侧最小化、最大化／还原、关闭按钮共用 `Button` 的 `ghost`／`icon-sm` 规格：28px 按钮、6px 圆角、17px Lucide 图标和 1.65 线宽，组内间距 4px。两组之间使用 16px 高的局部分隔；关闭按钮仅在悬浮时使用危险语义色。
- 标题栏标识、留白及非交互边缘用于拖动，双击切换最大化；导航、应用操作和窗口按钮均排除拖动与双击最大化。窄窗口只允许导航局部横向滚动，当前目的地随切页和可用宽度变化保持可见，右侧操作不被挤出。
- 窗口命令调用既有 Wails runtime，最大化状态从原生窗口读取并随窗口尺寸和焦点变化更新；关闭沿用正常退出及资源清理。普通浏览器预览缺少原生 runtime 时禁用窗口命令。
- 此调整不改变公开 CLI、桌面业务 DTO、runner 协议、用户配置、数据库或历史报告格式，无需数据迁移。
- Wails 开发模式通过 Vite watcher 提供前端源文件，生产构建仍消费 `dist`，避免构建清理使已打开的开发窗口丢失延迟加载资源。工作区各自捕获页面模块加载和渲染异常，保留全局导航及其他页面状态，显示明确的重新加载入口；重新加载前告知未保存输入会重置。异常通过既有 runtime 诊断入口写入有界、脱敏日志，不把原始错误直接显示给用户。

## 工作区按需加载

- 应用外壳、导航和界面设置先显示。页面读取失败或尚未完成时，导航仍可使用；错误、重试与日志入口属于当前页面，不阻塞其他页面。
- 默认运行页按需读取运行工作区及分页 Job 摘要；选中受 Job 管理的执行后读取其关联报告摘要；模型与渠道页请求 `connections`，用例页请求 `definitions`；总览和计划编辑按其需要请求完整 `all` 目录。`GetCatalog(scope)` 的 scope 必填，不接受空值或未知值。
- 快速测试先挂载页面，页面代码、`connections` 连接配置、`definitions` 测试定义及独立历史分页并行加载；切换到性能测试或计划测试后才挂载对应表单，并请求包含内置及自建计划的 `quick_test` 目录。复用各范围的会话缓存，不读取完整运行工作区或报告目录。目录加载图标和失败重试图标放在对应选择框右侧，复用下拉箭头的位置；详细状态通过 Tooltip、键盘焦点和可访问名称提供，不在字段下方增加状态行。未就绪不显示空目录或缺失渠道错误，用户可先填写连接字段。功能提交等待连接与测试定义就绪，手动性能提交等待连接就绪；性能计划加载不阻塞手动配置。数据到达、重试及切页均保留输入与已有记录。
- 新建运行和新建渠道批量测试在打开操作面板时才读取完整目录。报告页进入时并行读取报告摘要与渠道批量历史，按时间倒序排列（普通报告使用生成时间，批量历史使用已有创建时间，同时间以类型和 ID 稳定排序）；每份子报告独立展示和勾选，保留批量历史记录的整组入口。批量历史独立显示加载、失败重试和更多历史入口，不阻塞普通报告，报告正文仍在打开、对比或导出时按需读取。运行页只在打开或跟踪批量任务时读取其报告数据。
- 同一资源共享进行中的请求，完成后缓存。写入结果覆盖缓存并使相关数据失效；失效前的旧请求不能覆盖新结果。离开页面后停止其进度轮询，重新进入时按需更新。
- 主导航页面首次访问才挂载；切换后保留本次会话内的数据、筛选、已加载分页、选中项、详情页签与各滚动区域的位置。隐藏页面暂停副作用和轮询，返回时立即恢复已加载内容，后台更新不重新显示首次加载状态；手动刷新仍提供操作反馈。保留状态不写入持久化格式，关闭应用后不保证恢复。
- 主导航（含 hash／前进后退导航）切页前统一关闭 Tooltip、下拉菜单、搜索候选、Sheet 和确认弹窗，取消待显示提示并释放模态锁；返回页面不自动重开。临时浮层不属于需保留的页面状态，关闭时不把焦点抢回旧页面。此行为仅调整会话内展示，不更改公开协议或持久化格式。
- 报告目录只返回最多 100 条摘要，不解码报告正文、不扫描证据和附件、不为缓存计算完整关联数据的哈希。打开或导出具体报告时，才校验该报告正文、附件、结果、证据及对应运行历史。
- 运行列表只聚合展示所需的结果状态和计数，证据与附件只读取数量；正文及关联校验留在对应对象的读取边界。运行摘要携带已生成报告的 `report_id`，查看报告按钮无需预读报告目录。
- 运行列表仓库端口使用独立的标量投影，只传递身份、冻结名称、负载、Case 数量及进度；不传递 `domain.Run`、完整快照或 Case 定义，也不重编码历史文档或检查全部修订历史。结果字段先缩为小型临时集合，再复用于运行统计和执行项统计，完整响应正文不进入窗口排序。列表仍验证当前格式、摘要字段、归属、计数和报告封存状态；深层定义及修订历史的异常在 `GetRun` / `GetRunRevision` / `GetReport` 等明确详情读取时报告，读取失败不改写数据。
- 启动保留当前数据库结构与版本验证，只读取上次未结束的运行进行中断恢复；全库 `foreign_key_check` 和 `quick_check` 由显式调用仓库的 `CheckIntegrity` 执行。没有运行时历史格式回退，也不会在读取时升级、重写或清除用户数据。

## 运行工作区

默认入口是“运行工作区”。普通测试、性能测试和渠道对比在同一列表中展示，按一次提交一条记录组织，不再提供独立任务抽屉。

快速测试历史由 `GetQuickTestHistory(after)` 每次读取最多 25 条功能运行／性能报告摘要，按时间、类型和 ID 稳定倒序，滚动接近底部自动追加，保留键盘可用的“加载更多”和失败重试入口。历史列表不再截断为 50 条，性能记录也不受报告目录 100 条上限影响。SQLite 先选择有界 ID 窗口，再聚合该页运行的结果、证据数量与报告结论；性能候选沿用现有纳秒时间索引。功能记录来源仍需检查当前运行快照，尚未新增来源／排序索引，不能据此宣称所有候选检索均为索引 seek。切页保留已加载历史、游标和滚动容器；返回时保留内容并后台刷新，隐藏期间停止轮询和触底观察。

本次仅新增随桌面前后端一起发布的历史读取绑定；现有工作区／报告读取契约、CLI、远程协议及持久化格式不变，不需要数据迁移，也不引入旧格式转换或弃用期限。

快速功能测试提交后立即在左侧测试记录中展示 Job 状态，不等待本地 Run 镜像出现；Run 同步后按执行身份合并为同一条记录。确认回执与实际执行状态分别展示，读取失败保留最后一次观测，不推断任务失败。快速功能测试表单下方不再重复显示执行详情；记录操作区通过带“执行详情” Tooltip 的图标按钮进入运行工作区。待同步记录的展示信息仅保留在客户端会话内，不保存密钥或提交载荷。

执行结束与报告在本地可读分开处理。快速测试记录在结束后显示“等待报告同步”和当前已加载记录中待同步的条数，直到本地报告可读才显示报告入口；不把执行进度当作下载百分比。远程事实／报告成功入库后通过桌面 `remote-results-changed` 无载荷事件触发合并刷新，连续通知合并为一次读取；未收到通知时，活动／待报告记录每 2 秒刷新，空闲页面每 10 秒补偿读取。已加载的旧功能记录按 ID 分批更新，性能报告按 ID 查询可读性，不受历史首页限制。隐藏页面停止这些订阅和轮询，返回时保留列表并刷新。此变更仅扩展随桌面前后端一起发布的内部事件，不改变 runner 协议、公开 CLI 或持久化格式，不需要迁移或额外升级步骤。

- Job 保留本地／远程提交、接收确认、执行器身份、连接观测及控制命令职责；Run 保留测试快照、用例结果、证据和报告职责。
- Go 的运行摘要投影提供可选 `job_id`：从本地或远程镜像的已有归属表读取，并校验归属。受 Job 管理的 Run 只作为所属执行的详情或子运行展示；未归属 Job 的独立 Run 仍可读取。无需修改存储格式或转换历史数据。
- 每次读取最多 25 条 Job 摘要；更多历史由用户显式加载。搜索、类型、执行位置、状态和套件／计划筛选作用于已加载记录，界面明确显示当前可见条数。快速测试按冻结的套件 ID 合并筛选选项，普通运行按计划 ID 筛选；同一套件多次运行不再重复列出临时计划，套件和计划名称前标明来源。
- 尚未创建 Run 的待确认提交与性能任务同样显示。投递状态、实际执行状态和网络可达性分别展示，不用失联推断执行失败，也不用子 Run 推断尚未确认的 Job 状态。
- 计划运行和独立性能测试共用详情面板的标题、状态、摘要／执行／失败／产物页签与固定底部操作布局。性能测试默认打开“摘要”，只展示已有观测中的模型、渠道、负载、完成进度和耗时；结果尚未同步时明确提示等待，不生成零值指标。完整性能报告通过底部“查看报告”打开，不嵌入详情面板。
- 详情中的“执行”页签提供执行位置、执行器身份、提交确认、连接观测和本客户端命令记录；重试沿用原命令 ID。普通、性能和对比任务共用固定底部的“停止发送”和“取消”，切换页签仍可操作，并展示命令发送、待确认及最终回执。“停止发送”等待已发请求结束，“取消”请求中断当前执行；远程离线或命令接收不代表取消完成。未获得执行器确认的任务展示暂不可控原因。页签切换复用同一观察器，底部报告入口仅在报告已同步到本地目录后可用。
- 渠道对比只占一条执行记录，详情中切换子运行，并可打开整组对比报告。
- 宽窗口使用 320px 详情栏；1180px 以下由“详情”按钮打开 340px 抽屉。同一时间只挂载一份详情观察器；离开运行页停止列表轮询，关闭详情或客户端不发送取消命令。
- 保留摘要、失败、产物和关联报告入口。校验、生命周期、结论和统计来自 Go；React 仅负责组织列表、筛选、选择与呈现。

## 报告与套件的可读性

- 报告目录支持搜索与报告类型、运行状态、模型、渠道、套件／计划组合筛选。筛选仅作用于已加载摘要；套件／计划沿用报告冻结的名称，不读取报告正文或当前目录推测历史归属。同名选项合并，渠道对比匹配任一参与渠道；独立性能报告和数据集评测不伪装成套件或计划。切换筛选和往返详情保留已勾选报告，清除筛选恢复全部已加载记录。

- 报告列表支持多选 2–8 份功能或性能报告进入[报告对比](report-comparison.md)，同一渠道不同时间的报告各占一列。搜索不清除选择，返回保留搜索和选择；报告详情也可加入对比。对比使用冻结定义与配置，由 Go 对齐测试项、标记条件变化、缺测、恢复通过与新增失败，并计算同条件、同单位且有样本的指标差值。界面支持基准切换、仅看差异、证据展开及导出，不改写原报告，不以当前目录重算历史结论。渠道批量测试继续保留，并将已同步的整组报告送入同一对比视图。

- 报告首屏先展示已有结论及少量关键指标，再展示完整指标。功能报告直接使用 Core 返回的失败、无法判定、通过及仅观测数量；性能报告展示请求成功率、SLO 达标率、TTFT P95、TPOT P95、E2E P95 和成功吞吐，采用一组紧凑摘要，默认桌面窗口下六项同排；内容区达到 800px 使用六列，560–799px 使用三列，更窄时使用两列。每项展示实测值、状态及目标或参考上限；达标项数和稳态样本数由 Go 读取投影提供，不增加下方重复明细。
- 六项核心性能指标各自使用 6px 圆角的语义悬浮底色，悬浮不改变数值位置和布局，也不表示可点击。达标项的数值、单位与状态统一使用通过色，未达标项统一使用失败色；浅深色主题及减少动态效果偏好保持一致。
- 核心性能概览保留现有六项与 P95 口径，默认参考标准为请求成功率 ≥99%、TTFT P95 <15 秒、TPOT P95 <40 毫秒、E2E P95 <30 秒、成功吞吐 ≥2 req/s，默认延迟上限采用严格小于判定。五项目标在 Go 读取投影中评估并参与评分，标注“参考目标”，不是历史报告当时配置的考核结论。参考目标需结合负载场景理解，尤其吞吐不是通用渠道容量承诺。报告已保存 E2E 单请求上限时优先沿用，保留其原有精度语义；SLO 达标率继续使用封存配置和结论，未配置不生成目标或达标率。缺少样本显示空值，停止或未评估的运行不补算通过。概览达标项数不等于请求成功率或 SLO 达标率；运行、逐请求 SLO、容量结论及历史数据保持原样，不能用当前参考目标覆盖。React 不计算考核结论。
- 渠道评分由 Go 在读取报告时按 `target_ratio_v1` 投影，不写回历史数据，也不改变既有 JSON 导出格式。仅有目标且已评估的指标等权参与：达标贡献 1；未达标的下限指标按实测/目标、上限指标按目标/实测，限制为 0–1，平均乘 5 后保留两位小数。显示五星、分数及参与项数，无参与项时显示暂不可用。评分可悬浮或聚焦查看规则；不同目标、负载下不直接排名。高评分仍独立保留未达标结论，状态文字右侧使用对应的通过、失败或未评估图标。桌面与 HTML 导出共用计算。
- 报告正文和桌面视觉导出不再显示下方独立的“SLO 与容量”明细区；核心概览保留已有容量状态。SLO、Goodput、违规计数和容量阶梯的封存数据及 JSON 导出不变。
- 普通报告的 HTML、PNG、PDF 与复制图片头部显示原报告冻结的生成时间，包含年份、秒和明确时区；再次导出不更新该时间。渠道对比的界面、复制图片及视觉导出共用精简展示：默认只有结果和差异标记，按当前用例展开状态包含详情；渠道标题及基准选择不显示时间，原报告时间仍保留在 JSON 数据中。
- 套件列表、详情、搜索及计划选取上下文使用已有 `description`。说明默认换行；缺失时显示“暂无说明”。不以计划说明替代套件说明，不推断未记录的覆盖范围。
- 此批改动仅调整界面与视觉导出；公开 CLI、runner 协议、Case/Suite/Plan 文件及历史报告格式不变，无需数据迁移。

## 界面缩放

- 界面设置提供 80%、90%、100%、110%、125% 五档应用内缩放，支持 Ctrl／⌘ 加 +、−、0，以及 Ctrl + 滚轮。偏好按版本保存在本机界面设置中；系统 DPI 不作为应用缩放比例。
- 缩放变化后短暂提示当前比例；非 100% 时，菜单栏常驻当前比例按钮，点击恢复 100%。所有主题与浮层共用根节点缩放，内容高度按缩放调整，页面本身不滚动。

## 语义设计 Token

所有组件只消费语义变量。禁止在 JSX 中使用主题专属的白、黑或任意状态色。

### 配色主题与明暗模式

## shadcn/ui 映射

| 需求 | 组件与约束 |
| --- | --- |
| 顶部目的地导航 | `Tabs` 或 `NavigationMenu`；当前项同时改变表面和文字，不只依赖颜色 |
| 主题偏好 | 界面设置内的 `DropdownMenu` 单选组；明暗模式为跟随系统、浅色、深色，配色主题为经典、高对比 |
| 运行数据 | `Table`，无外框、行列分隔线和表头/表尾边框；悬浮或选中时显示整行 6px 圆角背景，不包 Card |
| 状态 | `Badge` 的语义变体；详细原因进入 Tooltip 或检查器 |
| 搜索 | `InputGroup` + `InputGroupInput`，不绝对定位自制按钮 |
| 筛选 | `SearchableSelect`，统一支持输入筛选，提交值只能来自现有选项 |
| 候选建议并允许自由输入 | 共享 `Autocomplete`；候选仅辅助补全，不得使用无法随主题统一的原生 `datalist` |
| 新建运行 | 桌面使用 `Sheet`，窄窗口使用 `Drawer`；必须包含可访问 Title |
| 运行表单 | `FieldGroup` + `Field`；错误同时设置 `data-invalid` 与 `aria-invalid` |
| 长任务 | `Progress` + 固定任务条；不可测进度使用 `Spinner` |
| 持续错误 | `Alert`；短暂成功/失败反馈使用 `sonner` |
| 无数据 | `Empty`；加载使用 `Skeleton` |
| 分隔 | `Separator`，不使用手写 `<hr>` |
| 已选运行详情 | 开放式两行 description list；标签在上、值在下、无单元格边框 |

`className` 仅用于布局和尺寸组合。颜色、字体和状态外观通过组件变体及全局语义变量实现；不在 JSX 中写 raw color，也不写手工 `dark:` 覆盖。

## 表单与上下文交互

- 根据表单容器的实际可用宽度组织关联字段；短参数可并排，长文本与复杂控件保留足够空间。某个编辑器的列数和宽度不作为所有表单的统一模板。空分组不保留无意义的占位间距。
- 纵向字段的标签与输入区间距统一为 8px，由共享字段组件负责；开关、复选框等横向字段保持行内对齐。
- 选项优先显示可读名称；仅在区分选项或影响决策时附加协议、revision 等元数据，底层提交仍使用稳定标识。
- Sheet 内的下拉浮层复用共享控件的固定定位与容器解析，位于模态焦点边界内、滚动表单外。选择选项不关闭编辑器；Escape 先关闭当前下拉，再关闭 Sheet，并恢复到相应触发控件的焦点。
- 搜索区分无数据与无匹配，支持清除，从详情返回列表时保留查询。筛选后的选择与详情保持一致；本地匹配数仅描述显示集合，不代替 Go 的执行统计。
- 表格行选择、详情导航和上下文编辑按当前任务确定，不统一绑定为同一种点击动作。矩阵作为编辑入口时，已有单元格编辑当前记录，空单元格从所在行列预填新建表单，并保留校验、不可用状态、键盘操作与关闭后的焦点恢复。
- 输入框、文本域、输入组、候选输入与可搜索下拉默认无可见描边，仅用背景和圆角标识输入区域；字段式开关的外层同样无默认描边。保留透明的 1px 边框占位，聚焦时显示语义焦点色，校验错误时显示错误色，不额外添加外圈，也不改变控件尺寸。复合输入由最外层显示焦点与错误边框；复选框、单选框本体和其他控件保留各自的识别轮廓及可见键盘焦点。
- 表单分组、计划与渠道选择行同样不绘制默认外框，选择态以底色与选中标记区分；次要按钮使用轻底色，不绘制默认描边。字段分组的错误边框与按钮的键盘焦点继续保留。
- 文本输入、文本域、输入组、候选输入与可搜索下拉统一使用 `surface-control` 背景和 6px 圆角；禁用与只读背景使用 `input` 色的 50%，禁用文字使用 `text-disabled`。不降低整个控件的透明度，避免背景叠加造成深浅差异。复合输入由最外层绘制背景，内部输入保持透明；输入旁可用的操作按钮保留正常对比度。

## 计划测试

快速测试提供「功能测试」「性能测试」「计划测试」三个模式。三者保留相同的连接配置：渠道填充、基础或完整地址、可自由输入的模型 ID、协议和 API Key；连接草稿在模式切换时共享，临时密钥只保留在当前会话。计划候选随连接协议筛选；切换协议后清空不匹配的计划，保留连接输入。

计划测试读取既有内置及自建计划，预览完整执行顺序、各项负载参数和失败策略。提交使用现有计划启动、冻结快照、默认本地或远程执行器及凭据租约，保留计划身份和各执行项配置。只有显式保存为渠道才写入模型、渠道配置；临时运行不创建目录配置。

计划记录复用已有分页运行历史、执行详情、控制、回收与正式报告。收到回执即可再次提交，每次运行独立保留；运行结束后继续等待既有报告归档。历史报告使用封存事实，再次执行使用当前保存的计划版本。会话内记录回填连接元数据但不保存密钥；跨会话的临时连接历史需重新填写连接，原报告可直接打开。模式隐藏时暂停相应观察与轮询，返回保留表单和滚动位置。

## 状态矩阵

功能测试、性能测试和计划测试仅在本次提交请求尚未返回时锁定表单；收到 Job 回执后立即允许下一次提交，工作区与报告刷新在后台进行。每个已提交 Job 独立保留执行状态、进度、控制和报告入口；编辑参数、切换测试类型、回填记录或提交新任务不得覆盖已有任务。回执中的待确认、排队和运行状态继续按 Core 的事实展示，不自动重试提交。快速测试页统一在左侧记录列表观察任务，通过对应记录打开执行详情或报告；性能测试弹窗保留各次提交的独立详情，进度使用各自提交时的参数。

每个交互组件按适用范围实现：default、hover、focus-visible、active/selected、disabled、loading、empty、success、warning、error。状态不得改变控件几何；选中态必须同时具备表面与文字或图标变化。

运行工作区至少验证：

- 无运行、筛选后为空、首次加载、刷新失败；
- queued、running、draining、completed、failed、cancelled；
- 可停止发送、正在停止、可取消、正在取消、终态禁用；
- 长中英文名称、长 UUID、1000 条以上结果；
- 键盘导航、焦点恢复、Escape 关闭、Tooltip 与可访问名称。

## 布局与滚动所有权

- 应用根节点占满窗口并隐藏页面级滚动；Header 固定。
- 快速测试使用左侧测试记录列表与右侧配置区：左栏宽 240px，宽屏为 256px，顶部固定功能／性能／计划三个模式的单选分段控件；运行与历史共用一份列表，运行中展示进度、状态与统计。名称、模型、渠道和时间保持可读。左右分别拥有独立 ScrollArea，左栏从菜单栏下方延伸到底部，右侧表单以 800px 最大宽度居中，从当前测试类型标题开始，不重复展示页面标题和介绍。模式开关占满左栏宽度，文字位于滑块内部。切换模式保留连接和参数；记录整行可点击或通过键盘激活来回填参数，行内报告等操作独立触发。记录操作与时间同排，开始按钮位于表单右下角。
- 表格区域和检查器分别拥有 `min-height: 0` 与独立滚动容器。
- 滚动条为覆盖式 5px rail，不得挤压内容或破坏列对齐。
- 下拉选项、输入候选、菜单与子菜单同样使用共享 ScrollArea 的 5px 轨道和滑块、4px 边缘内缩，不保留原生滚动条箭头或占位槽。通过共享 `ScrollAreaRoot`、`ScrollAreaViewport` 和 `ScrollBar` 组合浮层；选项列表本身作为 viewport，保留筛选、ARIA、键盘自动滚动与焦点行为。列表高度同时受自身上限与浮层可用高度约束，不以 `scrollbar-width: thin` 代替覆盖式滚动条。
- 普通内容容器默认无边框。层次优先级：对齐与留白 → 字号与字重 → 少量背景差 → 局部分隔线 → 必要完整边框。避免用灰底块替代每个旧边框，禁止嵌套卡片和边框、背景、阴影叠加。
- 吸顶表头底层使用完整、不透明的矩形背景覆盖滚动内容，上层单元格使用默认 `table-header` 背景与首尾 6px 圆角；底层封住圆角和单元格间隙，禁止表头半透明或背景模糊。原生表格行不得使用 `content-visibility: auto` 或预估行尺寸，以免滚动时重新计算列宽、行高。
- 所有表格使用无边框样式，border-spacing 为 0，避免表头开始滚动时发生位移；共享表头默认固定在所属滚动区域顶部，圆角后方使用不透明矩形底色，并向下延伸 2px 隔开被遮挡的行；默认行背景透明，悬浮使用 hover surface，选中使用 active surface 且优先于悬浮。背景绘制在单元格，首尾单元格呈现 6px 圆角，中间保持连贯；不通过行本身的矩形背景填满圆角。固定列、矩阵、报告和请求明细同样适用，保留键盘焦点。
- 密集运行状态采用状态点＋文字，减少描边胶囊；输入控件默认以底色区分，聚焦与错误时显示描边，浮层和键盘焦点保留明确边界。
- 布局决定栏宽，内容适应栏宽。Flex/Grid 子项设置 `min-width: 0`，弹性 Grid 列使用 `minmax(0, 1fr)`。
- 内容溢出的默认行为是换行；长 ID、URL、连续英文和错误信息使用 `overflow-wrap: anywhere`。不得通过默认省略、裁切或撑宽详情面板来处理。
- 详情使用按视口宽度布局的 ScrollArea，宽表格、代码才允许局部横向滚动；同一区域只有一个垂直滚动所有者。
- 所有页面的固定详情栏统一为 320px；1180px 以下通过 340px 宽的右侧详情抽屉访问，保留选择状态。详情内容左右留白统一为 16px。
- 宽窗口保留运行列表与详情两栏；紧凑桌面把检查器移入 Sheet，筛选保留在列表工具栏，业务状态和命令保持同一来源。

## 验收锚点

- `1440 × 900`：运行列表与 320px 详情栏。
- `1024 × 768`：紧凑桌面，检查器不挤压主表格。
- 连续缩放经过应用断点两侧，无水平页面滚动、裁切或不可达操作。
- light、dark、system 三种偏好、首次绘制、系统主题变化和 overlay 同步。
- Browser/IAB 中走通：筛选 -> 选择运行 -> 打开检查器 -> 新建运行 -> 启动 -> 停止发送或取消。
