## 场景与执行规则

- T0：schema、加载、模拟响应、套件生成一致性；不访问供应商。
- T1：短输出功能调用。T2：带有效普通 API 凭据的参数入参拒绝，必须是 HTTP 400 和允许的 121x 参数码；鉴权独立使用 HTTP 401/100x。
- T3：长上下文、大工具数组、大输出预算、缓存、负载及外部工具环境；本目录全部禁用并从自动套件排除。
- max_tokens=1 只证明截断/usage 预算；不能要求最终自然语言内容。其余普通成功必须具有最终内容和正确 stop 终止；仅有 reasoning 不算业务成功。
- 函数调用使用 auto。边界接受用例允许正常文本或声明内的有效工具调用；调用生命周期用例明确要求固定 fixture 工具并校验参数，随后回传本地常量结果。
- 不验证不可观察的内部采样/推理档位是否真正采用。正例证明请求被接受和可见响应契约；质量、分布和内部使用行为保持 partial。
- 普通 API 不支持 reasoning_effort 别名；Coding Plan 映射别名且默认保留历史思考，不能直接套用本套件。
- 官方中文 stop schema 最大 4，英文正文仍说 1；4/5 边界模板不进入自动拒绝套件。
- 空值、无上限或未指定状态的稳健性场景保留为 characterization 模板，不臆造数值边界。
