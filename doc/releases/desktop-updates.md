# 软件内更新（v0.2.1 分支验收记录）

本功能随 `v0.2.1` 交付；以下保留合入前的分支验收事实，正式发布内容与升级步骤见 [v0.2.1 发布说明](v0.2.1.md)。

- 界面设置新增“软件更新”：启动自动检查稳定版本，可关闭自动检查、跳过版本，
  也可手动检查和下载。下载显示进度，支持取消和重新下载；关闭面板继续下载。
- Windows 安装版下载并调用对应安装器，便携版通过独立助手替换。安装需要
  明确确认，活动测试、后台工作或无法确认的任务状态会延后安装。助手等待软件
  退出后才安装，保留旧程序；安装器仍在运行或状态未知时不重启软件。
- macOS 可在软件内下载、校验并打开 DMG，再手动拖放安装。首版不做静默替换。
- 发布流程先上传完整草稿，再公开版本；预发布不作为 latest，公开版本不覆盖。

首次使用需要手动安装一个带此功能的版本。当前公开的 `v0.1.4`、`v0.1.5`、
`v0.2.0` 不会凭此自动获得更新入口。后续更新源仍是本项目 GitHub Releases，
只接受更高的普通三段稳定版本；开发版、预发布构建及其他平台保留发布页入口。

新增独立的更新偏好 schema 1；已有配置、数据库、Case/Suite/Plan、快照、历史
报告、公开 CLI 与 runner 协议不变，无新增数据库迁移、弃用或移除期限。
既有工作区仍按原支持窗口升级，旧 `v0.0.01` schema 7 不因此增加升级支持。
远程 runner 不会随桌面端自动更新，版本组合继续执行原能力门禁。

程序备份不等于工作区备份。新版启动后可能迁移数据，降级应按对应发布说明
恢复匹配的工作区备份与程序；旧备份不包含其后新增的数据。

校验使用固定 GitHub HTTPS 更新源、SHA-256 和可用的资产 digest。本次没有
配置独立更新签名、Windows Authenticode 或 Apple 签名／公证；正式发行的
系统安装及签名状态需单独验收。

本次验证包括 Go 更新及桌面桥接回归、Windows 真实助手的退出／替换／重启和
无法启动时恢复、安装器进程超时、前端交互及严格 DTO、类型检查、lint、构建，
以及六种草稿发布／失败分支的隔离命令验证。原生 Windows 程序在独立工作区
访问实际 GitHub，确认 `v0.2.0` 为最新稳定版；界面检查覆盖三种桌面尺寸、
浅色／深色／系统主题、安装确认、任务保护及键盘焦点恢复。

最终前端全量回归为 83 个文件、1180 条测试全部通过（两个 worker，单测超时
20 秒）；Go 更新、桌面桥接及数据集后台工作回归和 `go vet` 通过。Wails 模块
与 CLI 保持 `v2.15.0`；生产前端及 Windows 原生程序构建通过。没有推送 tag、
公开 Release 或执行实际用户数据升级。

未对本机执行系统级安装器覆盖，未进行 macOS 原生拖放安装；已交叉编译 macOS
更新模块。竞态检测因当前 CGO 未启用而未能执行。全量 Go 检查中的
`engine/apiaudit.TestCLILoadsAllCurrentProtocolsAndRejectsOldDataWithoutWriting`
存在期望 1198、实际 1216 的目录计数失败，已在未修改的基线 `5f969847` 复现，
此变更未调整该计数。

更新边界、恢复方式和格式说明见[软件内更新设计](../design/desktop-updates.md)。
