# LLM Test Studio v0.2.2

本次基于 `v0.2.1`，修复 Chat 流式最终用量识别，并统一报告列表的状态标签。

## Chat 流式最终用量

- 最终 `usage` 与带 `finish_reason` 的结束 chunk 合并时，不再被误记为缺失；继续接受 finish 后 `choices=[]` 的独立用量块。合并块可以携带最后一段正文，也可以使用空 delta。
- 最终用量仍需恰好一次。缺失、重复、仅有提前用量、未完成流及结束后继续输出仍会失败；缓存读写和 TTL 的断言保持原样。
- 这是对兼容渠道返回行为的支持，不代表供应商新增了官方契约承诺。

## 报告状态标签

- 常规报告的用例列表与渠道对比矩阵、视觉导出统一显示一个整体校验状态标签。
- 缓存读写和 TTL 的分项结果及依据继续保留在展开详情中，历史结论不重算。

## 升级与兼容性

- 桌面、CLI 和远程 runner 共用解析修复；远程执行需单独更新 runner，桌面更新不会自动更新 runner。旧 runner 仍使用原识别规则。
- 保留 `v0.2.0` / `v0.2.1` 的输入，以及现有 Case/Suite/Plan、CLI/API、任务、快照、报告和数据库格式。本次没有数据迁移、弃用或适配移除安排，也不修改历史记录。
- 降级恢复旧版较严格的识别规则，无需新增格式转换；既有功能与数据的降级限制继续适用，见[兼容性政策](https://github.com/894x/llm-test-studio/blob/v0.2.2/doc/compatibility-policy.md)。升级前保存编辑、等待在途任务结束并备份工作区。
- Wails 模块与构建 CLI 均保持 `v2.15.0`，Go 构建工具链保持 `1.26.11`。
