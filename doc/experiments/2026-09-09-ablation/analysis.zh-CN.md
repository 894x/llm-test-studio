# LLM Test Studio 消融实验分析

日期：2026-09-09。分析对象是测试平台自身的能力贡献，不是某个 LLM 的参数或模型结构。

结论：本轮局部实验直接证明，SSE 契约检查与 SLA 门槛对阻止误放行有独立贡献；成功样本筛选决定了性能指标的含义。应优先保留这三项。开放环调度、不可变快照和边界用例体系也有明确的实验价值，但本轮没有完成它们的移除对照，不能据此给出实测贡献排名。

## 基线与方法

- 基线：`main`，HEAD `6fb3087ca19657a591eee53fb468e50ba11c1f87` 加当时未提交的工作区内容。不能把结果归属于该提交的干净版本。
- 环境：`go1.26.6 windows/amd64`。
- 使用 Go `-overlay` 将实验版本送入编译器，原业务源码和原测试文件均不改写。每组只移除一个因素，其他输入与测试一致。
- 基线运行 5 个顶层测试，其中 SSE 测试包含 7 个子测试，全部通过；不能将父测试与子测试相加称为 12 个独立样本。
- 三个消融版本均成功编译，并触发预期的行为断言失败。消融组测试失败是实验观察，不代表原项目回归失败。
- 本轮是一次确定性夹具的局部软件消融，结合已有回归测试；未调用真实供应商，没有测量真实故障发生率、生产收益或运行开销。
- 图工具先定位符号并追踪调用，coverage 提示相关文件元数据变化后直接读取当前源码。查询期间索引代次从 `2026-09-08T18:09:30Z` 更新至 `2026-09-08T18:11:57Z`，本报告以源码和本地执行为证据。

## 已执行的单因素对照

| 组别 | 精确消融操作 | 基线 | 消融后 | 可得结论 |
|---|---|---|---|---|
| A：SSE 契约 | `requireValidStream` 保留 HTTP 状态检查，移除帧数、内容、finish 和 DONE 检查 | 6 个异常全部拒绝；1 个正常接受 | 只拒绝 HTTP 500；5 个 HTTP 200 异常均接受；正常仍接受 | HTTP 成功不能替代流契约检查 |
| B：SLA 门槛 | `evaluateSLA` 保留观测计算，但返回空问题列表 | 1500ms 超过 1000ms 阈值，报告 fail | 同样输入生成 `Passed:true, Verdict:"pass"` | 请求成功与性能达标必须分别判定 |
| C：样本筛选 | 聚合分布的成功样本改为全部样本，其他逻辑不动 | E2E 均值 15ms，P95 19.5ms，样本 2 | 均值 343.3333ms，P95 902ms，样本 3 | 指标名称必须附带样本范围与分母 |

### A：SSE 检查贡献

固定一个合法观测：HTTP 200、3 帧、内容 `OK`、一个 finish、存在 DONE。分别只改变一个字段，形成缺少 DONE、缺少 finish、重复 finish、空内容、仅一帧这 5 个异常；另外加入 HTTP 500 和正常对照。

在这个人工构造集合中，异常拒绝数从 6/6 降为 1/6，误放行数从 0/6 升为 5/6。若只看 5 个 HTTP 200 契约异常，则全部漏检。该比例只描述这 6 个夹具，不能外推为线上漏检率 83.3%。夹具直接进入校验函数，不覆盖 HTTP 解析器、截断读取或真实 SSE 网络行为。

源码入口：[openai_evaluators.go](../../../engine/apiaudit/openai_evaluators.go)，`runOpenAIBlackBoxEvaluator → requireValidStream`。消融只覆盖这个共享校验路径，未声称覆盖所有供应商专用流解析器。

### B：SLA 门槛贡献

复用 `TestGeneratorFailsConclusionWhenObservedSLAIsBreached`：请求与 Case 的成功维度均为真，E2E 为 1500ms，快照内 `e2e_p95_ms` 阈值为 1000ms。移除 SLA 问题传递后，已有测试实际捕获到通过报告；正常报告控制测试仍通过。

这里证明的是一个明确反例：依赖请求成功状态，无法替代报告层 SLA 判断。没有测量多个阈值、空样本或未知指标的贡献，也没有证明所有 SLA 入口均受本消融影响。

源码入口：[generator.go](../../../internal/application/reporting/generator.go)，`Generator.Generate → evaluateSLA`。

### C：样本范围贡献

固定两条成功请求 10ms、20ms，以及一条失败请求 1000ms。消融前后请求数据完全相同。

- 成功样本均值：`(10+20)/2 = 15ms`；全样本均值：`(10+20+1000)/3 = 343.3333ms`。
- 聚合 P95 使用当前实现的线性插值，从 19.5ms 变为约 902ms。
- 两组成功率均为 `2/3`；失败并未从成功率分母消失。
- 已有细粒度流指标测试也检测到统计口径破坏。

不能据此说成功样本筛选让模型“快了 22.9 倍”。两者测量的是不同总体：成功请求体验与所有尝试的耗时。合理报告应同时显示成功请求延迟、失败率、失败原因和失败耗时，避免只展示成功延迟造成幸存者偏差。

源码核验还显示，报告聚合分位数与部分 SLA 分位数目前采用不同样本/计算路径：聚合延迟用成功样本和插值，SLA 分位数分支使用全样本和 nearest-rank。因此界面上的聚合 P95 不应未经核对就等同于 SLA 判定值。这是口径核验发现，未在本轮修改或断言为产品缺陷。

## 项目级其他消融维度

以下是基于当前结构的后续实验设计，不是已经完成的消融结果。

| 因素 | 对照如何构造 | 主要衡量指标 | 应控制的变量 |
|---|---|---|---|
| 开放环到达调度 | 固定服务响应脚本，开放环与完成后补发的固定并发对照 | offered/launched/completed、在途数、调度延迟、超时、容量拐点 | 请求内容、服务延迟、窗口、到达种子；显式报告实际负载不同 |
| 不可变 Run 快照 | 执行后修改当前 Case/Plan；对照实验版本改用当前目录重建报告 | 历史报告漂移数、原输入可恢复率、证据关联一致性 | 使用临时存储与相同初始目录，不改用户数据库 |
| 负例与边界用例 | 从固定协议/模型 Suite 中移除经人工确认的负例或边界集合 | 已知故障检出率、误放行率、调用数、耗时、费用 | 相同注入故障集；不能以通过率上升作为质量提升 |
| 多轮与重复探测 | 多次/多轮探测对照单次请求 | 间歇错误检出率、状态保持错误、每个新增检出的成本 | 随机种子、轮次、上下文、token 预算、响应脚本 |
| Evidence 与报告 | 同样执行，只在隔离分析版本移除证据收集或关联 | 根因定位准确率、定位耗时、可重放率、存储开销 | 同一错误任务，盲测操作者；不能用请求成功率评价此模块 |
| 桌面端与 CLI | 同样任务分别通过两个入口执行 | 结果一致性、配置错误率、操作耗时 | 同一快照、环境和执行核心；这是入口价值对照，不是引擎能力移除 |

额外运行了 `TestRunOpenLoopLaunchesOnScheduleWithoutWaitingForInflightRequests` 和 `TestRunSnapshotIsCompleteAndDefensivelyCopied`，均通过。前者确认当前实现可在请求未完成时继续发出计划请求；后者确认外部修改输入或返回快照不会改变已存快照。它们只验证当前行为，没有量化移除后的损失。

## 用例资产盘点

调用项目现有 `audit_case_coverage.py`，范围为整个 `data/cases`，未限定模型：发现 711 个 `case.json`，其中 426 个满足 `enabled=true` 且 `execution_mode=automatic`；断言 kind 的名称启发式将 243 个标记为负例候选。

这些是文件级结构计数，包含工作区未提交内容，不是某个模型实际可运行的 Suite，也不意味着 426 次请求。不同协议、模型、重复探测和手动/禁用项不能混成同一个实验总体。243 是启发式候选数，不是人工审核后的真实负例数。完整清单见 `catalog-inventory.json`；没有进行供应商官方契约完整性审计。

## 取舍建议

1. 将协议检查、明确 SLA 和带样本范围的指标作为验收核心保留；本轮有直接对照证据。
2. 提供不同成本的执行集合，例如连通性、核心契约、边界、负载，减少请求量时保留检查语义。不要通过弱化断言提高通过率。
3. 容量结论优先做调度对照；证据链价值优先做历史漂移与定位实验。它们不应按同一个“通过率”指标排名。
4. 多因素交互尚未测量。例如先取消协议检查会改变哪些请求进入成功样本，从而间接改变性能结论；本轮单因素差值不能直接相加。

真实服务阶段应固定模型版本、渠道映射、Case 修订、输入输出预算和缓存条件，交错执行完整组与消融组；按时间块配对分析差值，并同时报告不确定性、失败、超时与实际成本。样本量应根据先导实验方差和最小有意义差异决定。本轮没有启动这部分实验。
