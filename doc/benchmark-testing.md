# 数据测试（Benchmark）

数据测试用于比较渠道在公开数据集上的表现。入口是「快速测试 → 数据测试」，
与功能、性能和计划测试并列。执行与评分由固定版本的 Inspect AI 和 Inspect Evals 完成。

「数据集」是独立的管理菜单，可以搜索目录、查看来源和下载状态，提前自动下载、
取消下载、重新尝试、校验或清理本地缓存。「用于数据测试」会打开数据测试模式并选中该条目。
不提前下载也可以直接开始测试：应用会先自动下载并校验所选数据，再调用模型。
管理页的下载动作不会调用模型。

## 开始一次评测

1. 在当前电脑安装可用的 [uv](https://docs.astral.sh/uv/getting-started/installation/)，
   然后在数据测试页面点击「准备环境」。应用会下载 Python 3.12 和锁定的依赖；
   这一步不会调用模型。依赖安装失败时可以重试。
2. 选择已保存渠道，或者填写接口地址、模型 ID、协议和临时 API Key。
   支持 OpenAI Chat、OpenAI Responses 和 Anthropic Messages。
3. 选择一个或多个数据集，并设置每个数据集的题数、重复轮次、并发数和输出上限。
   初次使用建议 2～20 题、1 个轮次；题数为 0 时运行整个数据集。
4. 点击「开始数据测试」。首次使用数据集时需要联网下载题目；某些数据集可能有
   独立的访问条件和许可证。模型调用按渠道规则计费。
5. 在左侧测试记录或「运行」工作区查看加载、样本进度和结果。可以取消排队或运行中的评测。
6. 每个数据集分别生成报告，可从运行详情或「报告」目录进入，并导出 JSON。

每次最多选择 16 个数据集，同次提交依次执行；不同提交保留各自的记录。当前电脑一次运行一个
Benchmark 提交，数据集内部按设置的样本并发数执行，最多接受 16 个未结束提交。
每个数据集含重复轮次的执行样本总量上限为 100,000；超过上限的任务会失败。
数据测试始终在当前电脑执行，不使用默认远程 Runner。

临时 API Key 只用于当前提交，不保存在测试记录或报告里。重新填充历史配置时需要
重新填写临时密钥；已保存渠道继续使用其现有凭证管理机制。

## 内置数据集

目前目录包含 24 个评测条目，包含不同年份、子集及提示范式；不是 24 个互不相关的基准家族。

| 数据集 | 主要能力 |
| --- | --- |
| ARC Easy | 基础科学知识和选择题理解 |
| ARC Challenge | 科学推理 |
| GSM8K | 数学应用题 |
| AIME 2025 | 竞赛数学和复杂推理 |
| MMLU-Pro | 多学科知识与推理 |
| MMMU · Multiple Choice | 图文多学科选择题，需要模型支持图片 |
| AIME 2024 / 2026 | 不同年份的竞赛数学 |
| BoolQ / DROP / SQuAD 2.0 / RACE-H | 阅读理解与离散推理 |
| HellaSwag / WinoGrande / PIQA / CommonsenseQA | 常识与情境推理 |
| MMLU Zero Shot / Five Shot | 不同提示范式的多学科知识 |
| TruthfulQA | 对常见错误观念的辨别 |
| BIG-Bench Hard | 较难推理 |
| AGIEval AQUA-RAT / LogiQA / SAT English / SAT Math | 考试风格的数学、逻辑与阅读任务 |

这里的 MMMU 是普通 MMMU 的选择题任务，**不是 MMMU-Pro**。
当前固定版本的任务清单没有接入 OCRBench 或本地 Kimi-Vendor-Verifier 的自定义
MMMU-Pro 任务，不能把两种任务的分数直接比较。初版只运行内置注册任务；
页面不执行任意导入的 Python 脚本。

当前清单使用不依赖额外裁判模型的原生评分任务。需要模型裁判或额外平台依赖的任务，
应先明确其配置与费用后再接入。

## 自动下载和本地缓存

下载状态来自后台实际任务和本地文件检查。数据源通常不会提供完整总大小，因此下载中
显示已缓存字节数和活动状态，不展示推测的百分比；大小包括下载及处理后的数据，
排除临时锁、诊断日志和 Inspect 查看器状态。完成后显示题目数、文件数、任务版本和缓存校验值。

每个工作区、每个数据集使用独立缓存。下载完成后，评测的数据加载使用本地缓存并禁止
Hugging Face 在线下载；模型 API 仍按所配置的渠道访问。失效、取消或失败的下载可以重试。
最多同时进行 4 个维护操作，每份缓存上限为 8 GiB。下载是独立的准备任务，取消一次评测
会停止等待和后续模型调用；如需同时停止下载，可在「数据集」菜单取消下载任务。

「校验缓存」会重新计算数据文件校验值。「清理本地缓存」需要确认，且不能清理正在使用的
数据集；它不删除历史运行、样本答案、分数或报告。原生 Inspect 日志中的本地图片引用依赖
数据集素材，清理缓存后需重新下载对应数据才能再次访问这些素材。

旧版 Inspect / Hugging Face 的共享缓存不被删除或接管。管理页展示本应用独立托管的缓存，
首次使用这项管理功能会重新准备所选数据集。

## 阅读报告

- **执行状态**反映任务是否完整运行。低分、答错与请求失败分别记录；完成不代表能力达标。
- **评测指标**保留 Inspect 的原生名称和数值，例如 accuracy、stderr。
  accuracy 的原始数值通常为 0～1；没有统一转换成通过率。
- **样本明细**包含题目、参考答案、模型输出、评分、提取答案、说明和 Token 使用。
  每次加载 10 个样本，分页顺序按保存的样本身份排列，不保证等于数据集原始题目顺序。
- **评测来源**记录 Inspect AI / Inspect Evals 版本、任务版本、数据集来源和输入指纹。
  输入指纹覆盖本次选择的题目与答案；图片 URL 的哈希不是图片文件内容校验。
- **评测配置**保留本次请求的参数。提供商支持的参数不同，例如某些 API 不支持随机种子；
  固定种子也不能保证远端模型完全确定性。

样本展示和 JSON 导出中的每个文本字段最多保留 12,000 个 Unicode 字符，评分数量等
也有固定上限。图片输入展示为文本说明；原生 Inspect 日志保留在私有 Benchmark 目录。
JSON 导出包含所有保存的样本，最多 32 MiB，超出时会明确失败。

比较两个渠道时，应保持任务版本、数据集、题数、轮次、提示词和生成参数一致。
小样本适合检查连接与流程；不能用少量题目的分数认定整体能力或真实模型身份。

取消、失败或关闭应用后中断的任务仍保留已保存的样本；重新打开应用不会自动恢复
模型调用。可以查看已有报告，再从历史配置发起新的提交。

## 存储与升级

评测环境使用 Inspect AI `0.3.287`、Inspect Evals `0.27.0` 和随应用交付的 `uv.lock`。
依赖与任务清单变化时会使用独立的运行环境目录。

Benchmark 记录使用版本为 1 的独立原子文件存储，位于用户配置目录下的
`llm-test-studio/benchmarks`，由桌面工作区的独占锁保护。原生 Inspect 日志按
`inspect/<report-id>` 保存，避免把运行编号和报告编号重复嵌套进 Windows 长路径。
现有 SQLite、Case、Suite、Plan、报告和远程协议不需要格式迁移。

下载元数据另存为版本 1 的文件，数据本体位于操作系统用户缓存目录下的独立工作区目录。
这些缓存可以重新生成，备份历史报告时无需复制它们；迁移工作区后可以重新下载。
未知或较新的下载元数据同样会被拒绝，不会猜测版本或删除文件来修复。

未知、新版本、不完整或损坏的 Benchmark 文件会被拒绝，应用不会重置或删除这些文件。
降级到不支持数据测试的旧版本会隐藏 Benchmark 记录；旧版本不会转换或删除该目录。
备份或迁移工作区时，应同时保留 Benchmark 目录及其对应的应用版本。
