# Kimi official multi-model foundation cases

All cases use the `openai-chat` wire protocol; Kimi names identify models, not protocols.

The desktop application packages the runnable Kimi cases under `data/cases/openai-chat` into four model-specific built-in suites. Each runnable case declares exact `model_targets`; shared cases are referenced by each applicable suite instead of being copied.

- The current model targets are `kimi-k3`, `kimi-k2.7-code`, `kimi-k2.7-code-highspeed`, and `kimi-k2.6`.
- The catalog exposes 70 enabled K3 cases across 11 dimensions. `Kimi K3 官方基础套件` references the 60 routine T1/T2 cases; 10 media-heavy T3 cases remain explicitly selectable but stay outside that foundation suite.
- `Kimi K2.7 Code 官方基础套件` and `Kimi K2.7 Code Highspeed 官方基础套件` contain 10 cases each.
- `Kimi K2.6 官方基础套件` contains 11 cases.
- The four suites reference 73 unique enabled HTTP/SSE cases. The desktop runner still checks model applicability when preparing a target run as a safety boundary for user-created suites.
- An empty `model_targets` list means all models for generic non-Kimi cases; runnable cases in this Kimi suite always use an explicit target list.
- K3-only cases cover always-on reasoning and `tool_choice=required`; K2.6 cases cover `thinking.type=enabled|disabled`; K2.7 Code and Highspeed share the preserved-thinking baseline.
- Shared protocol, usage, auto/none tool choice, structured-output, and fixed-parameter baselines are maintained once and target all four models.
- Specified-function tool choice is enabled as a negative case because it is incompatible with K3 while thinking is enabled. The historical `allowed_tools` compatibility extension remains disabled because it is not a current first-party baseline.
- K3 multimodal object/string inputs and malformed-shape cases are enabled as non-default T3 cases; their deterministic fixtures are retained in the case definitions.
- Thinking switch and compatibility-alias cases are disabled because Kimi-K3 officially requires thinking to remain enabled. Only the no-switch default-on baseline remains executable.
- Deterministic fixtures are generated by `tools/api-audit/fixtures/kimi-k3/generate_number_media.py` with an OpenCV/Numpy frame buffer: the PNG contains `7`, while the MP4 shows `3`, `7`, `4` in order.
- File-ID inputs require IDs created in the target provider account; the self-contained suite covers the base64 branch and does not fabricate file IDs that would create deterministic false failures.
- Kimi-K3's fixed sampling contract accepts the official exact tuple and expects HTTP 400 for representative values immediately below or above each fixed value. The omitted-parameter case remains the recommended baseline.
- The report's `must.tool_choice`, `must.thinking_switch`, and `must.structured_output` rows are derived aggregates, so they are not duplicated as no-op cases.
- The report's `note.content_filter` row requires supplier-side manual confirmation and is not represented as an automated pass.
- `load-profile-32k.json` records the report's 32K load scenario, but the regular `api-audit` run does not automatically execute that paid 160-request workload.

The K3 suite now covers the current first-party request contract with equivalence classes, numeric/cardinality boundaries, dependency tables, and workflow cases. See [coverage-matrix.md](coverage-matrix.md) for exact coverage, execution tiers, documentation conflicts, and the remaining runner gaps for preserved-thinking replay and signed request headers.

The current model matrix follows the official [model overview](https://platform.kimi.com/docs/api/models-overview), [thinking model guide](https://platform.kimi.com/docs/guide/use-thinking-models), and [tool choice guide](https://platform.kimi.com/docs/guide/use-tool-choice).

```powershell
go build -o .\bin\api-audit.exe .\cmd\llm-test-studio
.\bin\api-audit.exe audit list --suite openai-chat --cases-root data/cases

# Run the non-stream usage smoke case for Kimi K3.
$env:API_AUDIT_API_KEY = "<secret>"
.\bin\api-audit.exe audit run --suite openai-chat --cases-root data/cases --base-url "https://gateway.example" --model kimi-k3 --case must.usage_non_stream

# Inspect applicable OpenAI cases without submitting requests.
.\bin\api-audit.exe audit run --suite openai-chat --cases-root data/cases --base-url "https://gateway.example" --model kimi-k3 --all-cases --dry-run
```
